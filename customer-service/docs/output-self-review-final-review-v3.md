### 4.2 缺口：**未按 captain 裁定记为「已知残留」**，且**缺影响面与成本评估**

acceptance 原文要求：*「captain 已裁定为『**已知残留，本轮不修**』（理由：均非 blocker，不影响核心保证『输出前自审 + 不通过降级 + 绝不外发源码』；重开 `plugins/**` 冻结的代价与收益不成比例）。须核交付材料**是否如实记录**为已知残留（含影响面与将来修改的成本评估），**不得**要求本轮修。」*

**实测（逐条 grep 判读）**：
```
delivery.md 中「已知残留」命中 = 2 处（且均非指向这三项；§6 标题为「已知残留与措辞」，§6.1 讲 E7 残留）
delivery.md 中「非 blocker / 不影响核心保证 / 代价与收益 / 不成比例 / 重开冻结」= 0 命中
三项的状态词 = 「⛔ 需另立任务」「◑ 部分处置 … ⇒ 另立任务」
三项给出的不修理由 = 「本任务 outOfScope 明确含 plugins/」「会重开冻结窗口（已作废 5 个闸门）」
```

**问题（3 点）**：

1. **状态词语义相反**：材料记为「**需另立任务**」（= 欠一笔待办、预期后续必做），captain 裁定为「**已知残留，本轮不修**」（= 本轮接受、非欠账）。同一事实的两种写法，**对"本轮交付是否完整"给出相反指引**。
2. **不修理由的性质不同**：材料给的是**程序性理由**（outOfScope / 冻结窗口成本）；captain 给的是**实质性理由**（非 blocker、**不影响核心保证**、代价与收益不成比例）。读者只看材料会得出「只因作用域记账才推迟 ⇒ 下轮必须修」，而裁定的含义是「**本轮即接受为残留**」。二者不可互推。
3. **缺「影响面」**（acceptance 具名要求）：材料未写这三项**对访客/团队的实际后果**。据我实测，影响面是可写的具体事实，例如：
   - **F-5**：门禁插件缺失时**静默透传**未净化内容且**无告警** ⇒ 团队**无法从主机侧发现「门禁未装」**；核心保证在该分支**无兜底**（该点已在 t15/t43 记为 medium）；
   - **F-4**：**「访客是否真的看到图」在主机侧不可观测**（叠加契约 §2 第四来源「窗口内无回传亦记 `passed`」）⇒ `blockResults=passed` 与访客实际所见之间**缺必达留痕**；
   - **P9 AS 断言**：干净 EOF 已有条款但**无自动化断言** ⇒ 该类回归**只能靠人工补测发现**（本轮该缺陷正是这样被发现的）。

**因此该 acceptance 条 = ❌ 未满足。**
**requiredFix**：在 `delivery.md` 的 §6.7 表内（或其下新增一小节）为这三项**统一改标为「已知残留（captain 裁定，本轮不修）」**，并逐项补 **① 影响面**（上列三点可直接采用）**② 将来修改的成本评估**（改哪个文件、需重开哪一段冻结、与「代价与收益不成比例」的关系），同时保留 captain 理由链中的关键词（**非 blocker / 不影响核心保证「输出前自审 + 不通过降级 + 绝不外发源码」**）。**不得**要求本轮修。
