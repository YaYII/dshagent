## 3. 前端兜底路径（今天线上 10800）：**真实泄漏，两种形态**

### 3.1 形态 I —— 内层受控围栏标记 + 块体**原样出现在外层代码块内**

例 B（` ```python ` 内含**缩进** ` ```mermaid `）：

```
可见文本 : "说明：print(1) ```mermaid graph TD结束。"
结构     : <p>说明：</p><pre><code>print(1) ```mermaid graph TD</code></pre><p>结束。</p>
```

例 C（` ```python ` 内含**行内非行首** `x ```mermaid `）：

```
可见文本 : "说明：print(1) x ```mermaid y结束。"
结构     : <p>说明：</p><pre><code>print(1) x ```mermaid y</code></pre><p>结束。</p>
```

→ **受控围栏标记 ` ```mermaid ` 与块体文本以文本形式进入访客 DOM**，命中 **SRC1**
（「任何围栏块…其原始内容（含 ` ``` ` 分隔符、块体源码）不得以任何文本形式进入访客 DOM」）。
契约 §5 对此有明确要求：「普通代码块…整块原文照旧透传（N2③）。**但其中出现的图形围栏仍会被摘出**」——
该要求**在前端兜底路径上未实现**。

### 3.2 形态 II —— 块体源码作为**正文段落**出现（更严重）

例 A（` ```python ` 内含**行首** ` ```mermaid `）：

```
可见文本 : "说明：print(1)graph TD X[a] --> Y[b] 结束。"
结构     : <p>说明：</p><pre><code>print(1)</code></pre><p>graph TD</p><p> X[a] --&gt; Y[b]</p><pre><code> 结束。 </code></pre>
```

例 E（外层 4 反引号）：

```
可见文本 : "说明：graph TD结束。"
结构     : <p>说明：</p><pre><code></code></pre><p>graph TD</p><pre><code></code></pre><p>结束。</p>
```

→ mermaid 源码 `graph TD` / `X[a] --> Y[b]` **以正文段落 `<p>` 呈现**。
这**不是**「显示未渲染的代码块文本」——它**逃出了代码块**，读者会把它当成回答正文。
同样命中 **SRC1**，且观感上比形态 I 更严重。

**真机复核（真 Chrome + 线上 10800 页面，仅拦截 chat/stream）**：与 jsdom 结果**逐例一致**
（A/E 块体落 `<p>`；B/C 标记落 `<pre><code>`；对照 G 正常），`pageerror = 0`。

## 4. Q3：闭合判据不对称 —— **可触发，且正是形态 II 的机制**

两条分支的闭合判据**不同**：

| 分支 | 闭合判据 | 强度 |
|---|---|---|
| 受控分支 | `isClosingFence(line, char, minLen)` = `^[ \t]*([`~]+)[ \t]*$` + **同类** + 长度 ≥ 起始 | 严 |
| 普通分支 | **裸 `/^```/`** | 松（行首即算） |

**最小复现**（外层普通代码块 + 内层受控围栏）：
普通分支遇到内层围栏行即**提前闭合**，余下内容重新解析 → 内层块体落 `<p>`。

| 复现变体 | 结果 |
|---|---|
| 4 反引号 python 外壳 + 内层行首 ` ```mermaid ` | 块体落 `<p>` ← ★泄漏 |
| 3 反引号 python 外壳 + 内层行首纯 ` ``` ` 行 | 块体落 `<p>` ← ★泄漏 |
| 3 反引号 python 外壳 + 内层行首 ` ```js `（非受控） | 同样提前闭合，块体落 `<p>`（非受控内容，非 E7） |

**结论**：不对称**可触发**；触发条件是「普通代码块内出现行首围栏行」。它把块体推给段落分支，
是形态 II 的直接成因。形态 I（缩进/行内内层围栏）成因则是**内层围栏根本未被识别**（普通分支不摘图形围栏）。

## 5. 数据面可达性（触发面有多宽）

扫描真实 KB（`deploy/kb`，33 个 md，127596 行）：

```
{"kbFiles":33,"totalLines":127596,"totalFenceLines":0,"controlledBlocks":0,
 "indentedFences":0,"graphicsFenceNestedInsidePlainCodeBlock":0}
```

→ **KB 中不存在任何围栏块**（0 个受控块、0 个围栏行）。
因此该残留**不可能来自知识库语料**，只能来自**模型自行生成**的答案，
且需满足「把受控围栏**嵌在普通代码块内部**」这一较窄的排版条件。

### 5.1 提示词约束的效力（**关键限定**）

两处 preset 用**明文**规定了不得嵌套（实测原文，`presets/customer-service-guest/agent.cordis.yml:56`，
生产经 `deploy/profile/cordis.patch.yml:135` 的 `preset: customer-service-guest` 生效）：

> \* 块内不得嵌套围栏，块内任何位置都不得出现三个连续反引号；每块都必须用独占一行的三个反引号闭合。

**但该约束是"提示词级"、不是"强制级"**（实测依据）：

| 检查 | 结果 | 说明 |
|---|---|---|
| preset 是否生效 | ✅ 是 | `cordis.patch.yml:135` → `preset: customer-service-guest` |
| 是否有确定性执行点 | ❌ 无 | `grep -rn '不得嵌套\|连续反引号' plugins/` 仅 **1** 处命中，且是**测试对 prompt 文本的断言**（`gate-check.mjs:696`），**无校验器/门禁代码执行它** |
| 门禁是否会拦嵌套 | ❌ 不会 | 主机侧状态机反而把内层围栏**摘成真块**（§2），即**不报错、不降级新增** |

**因此**：该约束**降低**触发概率（模型被明确要求不得嵌套，且要求"不要为了举例而在正文里写出围栏标记"），
但**不消除**它 —— 提示词是**概率性**控制，模型仍可在长回答/举例时违反。
**结论：触发概率 = 低（提示词已抑制 + KB 无围栏语料），但非零（无确定性强制）。**
这与本项目自身的方法论一致：**凡是"靠模型自觉"的约束，都不能当作确定性保证**（这正是本门禁存在的理由）。

> **反证提示**：若认为该约束足够，则等于认为"提示词能保证输出合规" —— 而整个输出前自审机制的存在前提，
> 恰恰是"**提示词不足以保证**"。二者不能同时成立。

### 5.2 更宽的触发入口：**表格单元格**（preset 规则**未覆盖**）

逐个实测 8 个可能入口后发现：**表格单元格内的围栏标记会原样保留**，
而且这一入口**不在 preset 的"块内嵌套"禁令范围内**（禁令只谈"块内"，表格不是代码块）。
即：**即使模型完全遵守 preset，仍可经表格触达**。

| 入口 | 是否被 preset 禁止 | 实测结果 | 处置 |
|---|---|---|---|
| 代码块内嵌套（行首） | ✅ 明文禁止 | 块体落 `<p>` ← ★泄漏 | **R-D2 目标**（t18） |
| 代码块内嵌套（缩进） | ✅ 明文禁止 | 标记落 `<pre><code>` ← ★泄漏 | **R-D2 目标**（t18） |
| 正文写围栏标记（举例） | ✅ 明文禁止（"不要为了举例而在正文里写出围栏标记"） | 无泄漏（走降级占位） | 已堵 |
| 引用块内围栏 | ✅ 原则禁止 | 无泄漏（F-5 已修） | 已堵 |
| **表格（多行，表头无围栏 + 数据行含 ` ```mermaid `）** | ❌ **未提及** | **标记原样出现在 `<td>`** ← ★泄漏 | **见 §5.3** |
| **表格单元格含 ` ``` `（无语言）** | ❌ **未提及** | 三反引号原样出现在 `<td>` | **见 §5.3** |
| 孤立单行含围栏标记（不成表） | ❌ 未提及 | **无泄漏**（正常摘成降级占位） | 对照组 ✅ |
| 列表项含围栏标记 / 标题行含围栏标记 | ✅ 原则禁止 | 无泄漏（摘成占位） | 已堵 |
| 纯 python（对照） | — | 正常透传 | 正常 |

**表格最小复现**（真实渲染 DOM，非推断）：

```
输入   : | 场景 | 写法 |
         |---|---|
         | 流程图 | ```mermaid |

可见文本: "场景写法流程图```mermaid其次文字说明"
结构    : <table>…<tr><td>流程图</td><td>```mermaid</td></tr>…</table>
```

> **机制（实测校正，勿按"分支顺序"理解）**：`matchControlledFence` **本身能命中**表格行
> （实测：正则对 `| 流程图 | ```mermaid |` 命中于 `at=8`），且**孤立的单行**（无分隔行、不成表）
> 会被正常摘成降级占位、**不泄漏**：
> ```
> 输入 | 流程图 | ```mermaid |（孤立行，不成表）
> 结果 → 出占位「示意图暂时无法显示」，无泄漏 ✅
> ```
> **真正成因为"多行消费"**：表格分支从**表头行**开始整表消费，
> 而**表头行本身不含围栏** → 围栏分支在表头行上不触发 → 表格分支把**后续含围栏的数据行一并吞掉**，
> 围栏标记随 `esc()` 直接进 `<td>`。即 **"表头无围栏、数据行有围栏"** 才触发。
> 这与代码块嵌套（形态 I/II）是**不同成因**：那里是围栏分支被调用但只认行首/闭合过松。

### 5.3 触发概率的修正结论

原报告 §5 说"触发面窄（KB 无围栏语料 + 需模型自行嵌套）"。经 §5.1/§5.2 实测后**修正为**：

- **入口不止一个**：除"块内嵌套"外，还有**表格单元格**这一 preset **未覆盖**的入口；
- **但仍属低频**：preset 明确要求"**不要为了举例而在正文里写出围栏标记**"，
  并列出 5 种围栏形态供模型直接使用（模型**无需**在正文写围栏标记来举例）；
- **性质未变**：仍是**前端兜底路径专属**、**SRC1 级**，主机侧口径 B 不受影响（§2）。
- **结论**：**低概率、多入口、非零**。既然存在 preset 未覆盖的入口，就**不能**以"提示词已禁止"为由
  判定该残留可忽略 —— 这恰是 G-ANCHOR 第 2 例（用措辞代替行为）的反面用法。

   都会随之消除。
3. **若要单独修（即 t18 / R-D2）**，建议改动点按成因分列：

   | 成因 | 最小改动点 | 对应形态 |
   |---|---|---|
   | 普通代码块分支不摘受控围栏 | 块体扫描时识别受控围栏并摘出，交 `gateBlockHtml` | 形态 I / II |
   | 普通分支闭合判据过松（裸 `/^```/`） | 改用与受控分支同构的 `isClosingFence` 口径 | 形态 II |
   | **表格分支整表消费，数据行内围栏未被摘** | 表格的行级处理也须识别受控围栏（或把行交给前置的围栏检测步骤） | 表格入口（§5.2） |

   **需先开修复轮并重录基线**。
4. **关于判据**：建议**把 §5.2 的三个入口都纳入 R-D2 的验收**（代码块嵌套行首/缩进 + 表格单元格），
   而不是只修代码块 —— 否则修完代码块，表格入口仍在。
   但**不建议**为此新增 V3/V4 判据判失败：它是**已知且已登记**的残余。

### 两处工具陷阱（供后续复验者避坑）

**陷阱 1：缺 `enabled: true` → 门禁整体静默失效**

主机侧 `engine.ts` **不导出** `DEFAULTS`；构造 `OutputGate` 时若配置缺 `enabled: true`，
门禁**整体不生效**（全部 0 块、原文透传），会得到"全例都泄漏"的**假结论**。

**陷阱 2：缺 `answerWaitBudgetMs` → 收尾窗口静默失效（★本报告初版曾误报此项，已更正）**

`GateSettings` 的真实字段是（`plugins/output-gate/src/engine.ts:36–53`）：

```
enabled / maxBlockBytes / blockTimeoutMs / answerWaitBudgetMs / libraryLoadTimeoutMs / reportPath
```

**没有 `visitorWaitBudgetMs` 这个键**。本报告初版曾把 `tests/gate-check.mjs` 的夹具值
（`{ enabled, maxBlockBytes, blockTimeoutMs, visitorWaitBudgetMs: 3000 }`）当作"正确默认值"，
**该夹具本身有缺陷**：它含一个不存在的键、且**缺 `answerWaitBudgetMs`**。

后果实测（同输入两种构造）：

```
Math.max(0, undefined) = NaN → turnStart + NaN = NaN → while (Date.now() < NaN) 恒假
缺 answerWaitBudgetMs → settle = 0ms      ← 收尾窗口完全不等待（P7/T1 失效）
answerWaitBudgetMs:600 → settle = 600ms   ← 正常
```

**正确的构造值**（与生产 zod schema 对齐，唯一权威在
`plugins/output-gate/src/index.ts:86–96`）：

```js
{ enabled: true, maxBlockBytes: 32768, blockTimeoutMs: 200,
  answerWaitBudgetMs: 600, libraryLoadTimeoutMs: 8000,
  reportPath: '/api/guest/render-report' }
```

> **修夹具不属本报告范围**：`tests/gate-check.mjs:60–65` 的 `DEFAULTS` 自称"冻结默认值（需求 §10）"
> 却缺 `answerWaitBudgetMs`、含不存在的 `visitorWaitBudgetMs` —— **错在夹具，不在生产**。
> 已登记为独立修复轮（captain 侧 t19）。

**本报告结论是否受影响？——不受影响，已用修正配置重跑全部 7 例复验**：

| 例 | 修正配置下的 `text` | 块终态 | E7 |
|---|---|---|---|
| A | `""` | mermaid:render → passed | 无命中 |
| B | `"   "` | mermaid:render → passed | 无命中 |
| C | `"您可以用 "` | mermaid:**degraded** → degraded | 无命中 |
| D | `"```python\nprint(1)\n"` | mermaid:render → passed | 无命中 |
