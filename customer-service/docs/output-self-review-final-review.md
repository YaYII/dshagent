## 2. 决定性发现（Findings）

### F-1（blocker）表格单元格内的受控围栏：块体源码进入访客可见 DOM；**且主机侧同样漏**

**问题**：受控围栏落在 Markdown **表格**里时，**前端与主机侧同时漏判**，块体源码以正文形式被送达并显示。

**复现（真机，未经改写）**：自建同源桩服务把「模型原始输出」交给**冻结页面**（`557466d15a49023b`），走 `fence-fallback`（= 旧后端 + 新前端，即今日 10800 的组合）：

| 用例 | 模型原始输出（片段） | 访客可见文本 | 落点 |
|---|---|---|---|
| 标记+块体同格（未闭合） | `\| 流程 \| ```mermaid graph TD_SUB_SECRET \|` | `The diagram is temporarily unavailable… **graph TD_SUB_SECRET**` | **`<td>`** |
| 标记在格内、块体在下一行 | `\| 图 \| ```mermaid \|` + `\| 体 \| graph TD_SUB_SECRET \|` | 降级文案 + 下一格 **`graph TD_SUB_SECRET`** | **`<td>`** |

命令：`node /tmp/rev-tbl-server.mjs` + `xvfb-run -a node /tmp/rev-tbl-drive.mjs`（脚本原文齐全，可复跑）。

**主机侧同样漏（这是关键）**：把同样的输入逐字符喂入**真实引擎实例**（`node --import tsx/esm /tmp/rev-host-matrix-a.mjs`）：

```
[c2] 模型原始输出：'说明如下：\n\n| 项目 | 内容 |\n|---|---|\n| 流程 | ```mermaid graph TD_SUB_SECRET |\n| 备注 | 见上 |\n\n结束。\n'
     主机侧 text：'说明如下：\n\n| 项目 | 内容 |\n|---|---|\n| 流程 | '
[c3] 模型原始输出：'…| 图 | ```mermaid |\n| 体 | graph TD_SUB_SECRET |\n| 续 | SUBSECRET_ROW2 |\n\n结束。\n'
     主机侧 text：'说明如下：\n\n| 项目 | 内容 |\n|---|---|\n| 图 | '
```

文本被拦到单元格中间、其后**全部丢失**（`结束。` 等也丢）⇒ 主机侧不是"净化后照发"，而是**整段截断**。两个后果都属用户原话所指：

1. **拦截理由错误**（`decision: degraded`）：表格单元格里的围栏其实**没闭合**，主机侧把"未闭合"当成降级理由，而真实原因是**行内起始的受控围栏根本不在它的识别范围**；
2. **正文截断**（可用性）：模型在单元格里写了半句围栏后正常换行继续写的内容，被整段吞掉；
3. **前端表格分支的摘取口径也不符合契约**：`tableCell()` 只在该格**同时含闭合标记**时才摘（`/tmp/rev-vacuous.mjs` 用例 `t4`：`flowchart TD_SUB_SECRET --> B ```` ``` ```` 原样进 `<td>`），否则原样透传 ⇒ 与契约 §1「行内任意位置可识别」不一致。

**契约与条款依据**：
- 契约 §1：*「只要出现『≥3 个同类围栏字符 + 首个词是受控关键字』即按受控块处理，**不要求行首**」* / *「不得出现『围栏图被校验、行内图绕过』的漏洞」*；
- SRC1：*「任何围栏块在任何状态下，其原始内容（含分隔符、块体源码）不得以任何文本形式进入访客 DOM」*；
- E7 / AS-3（三出口 `grep -E '```(mermaid|chart|image|img|html)'` 无命中）。

**严重度按块体本身定**：若模型在表格单元格里写受控围栏，其块体（即图内容）**无论是否合法都会以文字源码显示给访客**——这正是用户投诉的那一类"错误内容直达访客"。

**现有验收为何是绿的（这比缺陷本身更重要）**：`web/guest/tests/gate-dom-check.mjs` 的用例 ③.9c③ 输入为
`| 流程图 | ```mermaid |\n`——**单元格里只有标记、不含块体**。真实浏览器对照实测（`/tmp/rev-vacuous.mjs`）：

```
用例（逐字取自 ③.9c③）            | 输入含块体 | 可见文本含块体 | 判定
a_existing                        | false      | false          | ✅ 通过（无可泄漏对象 ⇒ 空断言）
b_withbody（仅补上块体）           | true       | true 落点=<td> | ❌ 应为红
c_bodymultiline（块体独占一行）     | true       | true 落点=<td> | ❌ 应为红
```

⇒ **R-D2 的"三入口已封堵"结论在表格路径上不成立**；套件「79 项全通过」（我实跑，exit=0）**不构成**表格路径的证据。

**requiredFix**：
1. 统一判定范围：把「受控围栏起始」的识别从**行级循环 + 表格整表消费**改为**覆盖单元格内容**——要么在表格分支对每个单元格跑与行级相同的受控分支（含未闭合→占位），要么把表格行拆回行级循环处理；
2. 前后端**同一口径**：前端 `tableCell`（`web/guest/index.html:662`）与主机侧 `fence-machine` 必须使用同一组起始/闭合判据，且在契约中写明"单元格即行"的等价语义；
3. 补**非空断言**用例：块体**在**单元格内的三种排布（同格带闭合 / 同格未闭合 / 块体独占下一行），断言「可见文本无块体源码 ∧ 无标记」，并**先断言输入里确实含块体**（反证自检），杜绝 ③.9c③ 那样的空断言；
4. 主机侧补同类用例于 `plugins/output-gate/tests/gate-check.mjs`（当前**零**表格用例）。

### F-2（high）「不通过 ⇒ 定向修复 + 二次校验」在产品要求中被取消，且**未留任何替代补救**

**问题**：用户确认的方案取向含「不通过则**定向修复、二次校验**，仍不通过才降级」；实际实现的语义是**直接降级**（无修复、无二次校验）。

**实测证据**：
- `plugins/output-gate/src/index.ts:17`：*「…也不存在第二次模型调用」*；
- `requirements` §1 变更表第 1 行：RH 系列「定向重写」**整条删除**，改为 REP「输出前替换」——依据是 captain 2026-09-10 的拍板：「不通过必须由模型重写」**不是**产品硬要求；
- `U2` 追溯行自述：*「**部分满足 → 经重新定义后满足（须 captain 确认）**」*，并写明**若产品真意是"必须让那张图正确地显示出来"，本取向不满足**。

**为什么仍要判 finding**：这条**已经影响到真实结果**——`/tmp/rev-host-adv.mjs` 的 `嵌套两层` 用例中，外层 ` ```mermaid ` 命中降级后，**内层 ` ```chart ` 的合法内容被一并丢弃**（`text` 只剩 `"```\n"`）。也就是说，"不修复"不是"少一次补救"，而是**把本可正确渲染的内容一起降级**。在没有二次校验的前提下，判据的质量就是内容的命运。

**requiredFix**（二选一，必须显式落纸，不得再由实现方默解析）：
1. 若确以「改完才给用户看」为冻结语义：在**交付说明**中显式写明「本机制**不包含**模型重写/二次校验，未通过即降级」及其**代价**（本可显示的内容会被丢弃），并由产品方**书面确认**——当前仅存在于需求文档的**追溯表**与代码注释里，交付面向读者的表述里没有；
2. 若产品仍要求"定向修复"：补回**有限次**的定向修复（同一轮内、块级、不阻塞 `done`），并给出二次校验与仍需降级的收尾判据。

### F-3（high）判据与实现的缺口：**裸围栏文本穿过主机侧**（` ```\n` 进载荷）

**问题**：`/tmp/rev-host-adv.mjs` 的 `嵌套两层` 用例（` ```mermaid / A / ```chart / SECRET / ``` / ``` `）中，主机侧 `text` 输出 `"```\n"`——**裸三反引号序列进入访客载荷**。

**为何是缺陷**：SRC4 与 §5 快照全局判据明写 *「`.bubble.innerHTML` 中不得出现 ` ``` ` 序列」*，AS-3 也以 `grep` 围栏序列为准；此处主机侧自己把该序列交给了访客。**根因**：主机侧不跟踪**普通代码块**的嵌套状态，遇到外层受控围栏被摘后，剩余的外层/内层普通围栏标记按原文外发。

**requiredFix**：在 `fence-machine` 补充「普通围栏块嵌套受控围栏」的状态跟踪：外层普通块内的受控围栏摘出后，其**残余围栏行**必须同样被消费（不得外发），并把该用例加入 `gate-check.mjs`；同时把 SRC4 的判据从"DOM 层"上移到**载荷层**（`text` 断言），因为 DOM 层已证明会漏（本文件 F-1 即一例）。

### F-4（medium）降级即不可读：`c1`/`c4` 等**通过判据的块**在访客侧仍然只看到"暂时无法显示"

**问题**：主机侧载荷 `blockResults` 记 **`passed`**，访客实际看到的是**降级文案**，两者不一致；且**没有任何留痕**。

**实测**（真机 + 冻结页面 + 真实主机侧载荷）：

| 用例 | 主机侧 `blockResults` | 访客可见 | 一致？ |
|---|---|---|---|
| `c1` 段落内闭合 mermaid | `passed` | `The diagram is temporarily unavailable…` | ❌ |
| `c4` 表格内"整格闭合"围栏 | `passed` | 同上 | ❌ |
| `c5` 普通代码块内嵌受控围栏 | `passed` | 同上 | ❌ |
| `c7` 有效 `image` | `passed` | `The image is temporarily unavailable.`（无 `<img>`） | ❌ |
| `c9` 有效 `chart` | `passed` | 条形图正常 | ✅ |
| `c8` 有效 `html` | `passed` | 沙箱 iframe 正常 | ✅ |

`c7` 的**根因已定位**：页面 `toImageSrc()` 把白名单路径拼成 **`${API_BASE}/uploads/…`**（`API_BASE` 由页面路径推导）；同源桩服务只暴露 `/assets/**` 与 `/api/guest/**`，**未代理 `/uploads/**`** ⇒ 404 ⇒ `naturalWidth=0` ⇒ 降级。这是**桩环境的产物**，**不构成本缺陷的证明**；但它暴露的事实是真实的：**契约把侧信道全推给真机，而真机一旦判负，`blockResults` 仍记 `passed`**（契约 §2 第四来源），于是**"访客看到的是降级"这件事在主机侧零留痕**。

**为何仍要判 finding**：用户问的是「出的图是否**通过**才能输出」。当前"通过"的判据在主机侧**不可见**：`passed` 有四种来源，其中第四种（窗口内无回传）**不蕴含**访客看到了图。因此**「图确实显示成功」这一条，现有证据链不足以支撑**——必须把"访客实际终态"做成可核事实。

**requiredFix**：把**真机终态**（`outcome` + `reason`）作为**必达留痕**（现 `flushFallback` 只对 `text` 变化留痕；`c1` 因 `text` 未变**完全无 trace**）；并在交付说明中把「`passed` 不等于真机已验证」从契约内部注记提升为**面向读者的显式声明**。

### F-5（medium）「不可绕过」在注释中被声明为唯一保底，实际存在**无警不降级**的旁路

**问题**：`plugins/guest-server/src/index.ts:259-264` 注释写 *「缺失即降级为『不净化』——桥本身仍然…」* 且紧邻一行 `logger.warn`；但**流式路径的实际分支**是 `index.ts:563`：`gate === undefined || !gate.enabled` ⇒ `turn = undefined` ⇒ 每个 delta **原样**走 `onGate({type:'text'})` 下发。两个后果：

1. **不降级**：与 C8 冻结顺序（*「丢弃该块（保留前后文字）> 整条回答失败」*；*「把未校验的块直接渲染在任何分支下都不是选项」*）冲突——此处是**未校验内容直接透传**；
2. **无留痕**：该分支**不调用 `ctx.logger`**，静默发生；而 `stats()`（留痕聚合）**零消费方**（全仓仅声明与实现，无调用点，也没有任何 HTTP 路由暴露）⇒ 团队不会知道门禁没装。

**requiredFix**：① 该分支必须**至少留一条 warn 级留痕**并计入 `stats()`；② 明确 C8 在该分支的语义（降级块 or 整体失败），不得留"不净化但继续"这一静默档；③ 二选一处理 `stats()`：接进一个可观测出口（日志汇总/健康端点），或删除该抽象（Q5：不留未使用抽象）。

### F-6（low）P9 类缺陷（干净 EOF）不是孤例，而是**枚举式条款**的必然产出

P9 只枚举「SSE 断流 / `AbortController` / 45s 硬截止」，**「干净 EOF」（有 delta、无 `done`、连接正常关闭）不在任一枚举项内**，导致该类**同时逃过条款与验收**（验收脚本由条款推导），只能靠对抗性补测发现（P9-1，现实已由 t22 修复，**条款补全仍未做**）。同一结构在别处**已再次发生**：F-1 的表格路径同样不在任何枚举项内。

**requiredFix**：按既有结论补 P9 四情形 + AS 断言，并把「枚举式条款须显式声明其余情形如何处置」升为**写条款时的强制项**（本轮已定稿为纪律，但尚未写入 `requirements` 正文）。

## 3. 工程质量与交付事实

**符合约定（已核）**：函数式插件导出形态；`ctx.get('outputGate')` 取可选服务；`ctx.provide` + `ctx.effect` 可回滚（`index.ts:256-262`）；配置经 Schemastery `Config`（zod schema 六键齐备）无硬编码；未新增第三方依赖；纯逻辑砖块（`output-gate.js` 无 DOM 依赖）与 DOM 组合分离清晰。

**不足**：
- `stats()` 未使用抽象（见 F-5③）；
- 测试资产分布不一致：主机侧 `plugins/output-gate/tests/{gate-check,http-exits-check}.mjs` **无表格用例**；前端有表格用例但**是空断言**（F-1）。⇒ 「两侧判据必须同口径」这一条**只在前端被写了测试，而那个测试是绿的**，恰好掩盖了缺口。

**交付事实清单（据本报告实测，供交付说明直接采用）**：

| 条款 | 事实 | 依据层级 |
|---|---|---|
| 1 | **本机制从未在生产运行过**：10800 为混合制品（前端 bind-mount 实时 / 后端为门禁改造前镜像） | 行为层（health 版本、`render-report` 404）+ 代码层 |

## 4. 方法与方法论（本轮可复用的判据纪律）

**新增 3 例（本轮产生，均有实测支撑）**：

1. **反证必须自带「生效性自检」**：先断言"被关闭的判据确实被关闭"，再据以判断修复是否有效。我第一版反证把替代实现**追加在 `src` 之后**，被同名 **function declaration hoisting** 覆盖 ⇒ 反证"关不掉" ⇒ 得出错误结论。
2. **判"是否泄漏"必须双信号**：同时查「围栏标记」与「块体源码」。单信号必漏一类——入口①只泄漏块体（标记不出现），`stripCr` 失效时两者同时出现。
3. **测试绿灯须配"空断言自检"**：凡断言"某物不得出现"的用例，必须**先断言该物在输入里确实存在**。③.9c③ 即因输入里根本没有块体而恒真（F-1 的反证）。

**既有纪律（本轮再获证实）**：
4. **「工具适用域」**：判据/脚本只在**其适用环境**内成立——jsdom 不做布局（`getBoundingClientRect` 恒 0），故几何类判据不可在 jsdom 层下结论；本轮我据此把「有效块真的渲染出图」放到**真 Chrome + 冻结页面 + 真实主机侧载荷**三段拼接上取证。超出适用域的结论一律不采。
5. **「文本检索不到」≠「不可核」**：`a9e38968` 的核验对象是**文件本身**，不是文档；
6. **穷尽清单必须四件套**：枚举域（是否递归/含哪些目录）+ **多判别列（不是一列）** + 归并口径（文件/哈希）+ **显式非穷尽声明**；数字只作**带时点记录值**，永不作为判据。本轮穷尽清单被实物扫描连续推翻四次（4 → 14 → 22 → 30），**第五次复核（reviewer 独立复跑）与 captain 一致**。复核时另得两条更正：① captain 的"接线态 15 个哈希"按**其自身口径**（`block-open≥5`）应为 **16**——漏 `f0dc41832`（`bo=6/gb=2`，即其基线事故条目引用的那份旧镜像快照）；② 「`block-open` 有 5/6 两值 ⇒ 计数不稳」的理由需改：`346ef51a` 为 `bo=5 且 mc=0`，**更像"接线早期版本"而非同版本计数抖动**——不存在单一判别器的结论不变，但正当理由是**不同时点的接线态取值不同**。**数字一律只记不判**；
7. **标签/结论必须回实验证**：**表格里的每一格都是一条断言**，未经实测的格子等于未验证（`07a073ce` 被标"门禁前原始页面"却实测 `block-open=6`）。本轮前四类是"**没写清在哪个域数**"，第五类是"**写完没回验**"，性质不同；**转述者也同责**——我亦曾采信该标签，故凡引用他人结论性表格，须回实体复算或显式标注"未核（转述）"；
8. **跨成员技术取值必须自验并标注「已自验/未自验」**：三跳转述链（t17 建议值 → captain 转发 → reviewer 转抄）由自查截断，不是由流程截断；
9. **判据不得内嵌易变事实**（G-ANCHOR-5）；**基线只含制品、不含 `tests/**`**——本报告 §1 的实跑会重写 `web/guest/tests/gate-dom-snapshots.json`（实测 `794811df23a0d4a7` → `6d745b87334ceaa4`），故**采样窗口内不得跑测试**。
